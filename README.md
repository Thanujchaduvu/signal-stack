# Signal Stack: Company Intelligence & Executive Briefing Engine

Enter any company name + URL → public-web research (verified facts vs assumptions) → adaptive 10-question interview →
AI-proposed, **live-verified** Signal Stack (Customers / Competitors / Market / Internal) → polite crawling with dedupe and history →
evidence-vs-interpretation analysis with transparent ranking → Monday Morning Brief. Weekly brief + monthly source audit run on a real scheduler (APScheduler); every run is logged and failures show in the dashboard.

Nothing is hard-coded per company: competitors, sources, interview questions and brief content are generated from the company's own research and your answers.

## Quick start (local)
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env     # set LLM_PROVIDER + a free key (Gemini or Groq) or run Ollama
uvicorn app.main:app --reload                          # open http://localhost:8000
```
Docker: `docker build -t signal-stack . && docker run -p 8000:8000 --env-file .env -v $(pwd)/data:/srv/data signal-stack`
Tests (offline, stubbed LLM): `pytest -q`

## Reproduce the demo (MeetUniversity + two other companies)
In the UI: **Company setup** → add `MeetUniversity` / `https://www.meetuniversity.com` → *Run initial research* → **AI interview** (answer as the founder; skip anything confidential) → *Build profile* →
**Signal stack** → *Build* → *Approve all* → **Intelligence feed** → *Collect now* → *Analyse* → **Monday brief** → *Generate*.
Repeat for two companies in different industries (e.g. a SaaS tool and a D2C brand) to show different questions, sources and briefs.
CLI alternative: `python -m scripts.run_demo --name "<Company>" --url <https://...>` writes `reports/<company>_brief.md`.
**Context-change test:** edit the profile (or answer text) → *Settings & jobs → Re-assess signal stack*: sources are re-scored, stale ones retired with reasons, new ones added, and the diff is shown.
Collect on at least two different days (or let the scheduler run) so page-change monitoring has a baseline to diff against; first visit of a page only stores a baseline and reports nothing.

> This repository ships **no pre-collected data and no sample reports**: they must be generated by running the app against live sources with your own LLM key. I could not do that during authoring (no network/LLM key in the build sandbox), so the 20-source / 30-record / 3-report targets are demonstrated by *you* running the steps above and recording the demo.

## Architecture
FastAPI + SQLite (single file `data/signalstack.db`) · vanilla-JS dashboard (no build step) · APScheduler · httpx/trafilatura/feedparser · `ddgs` search.
See `docs/TECHNICAL.md` (architecture, discovery, crawling, ranking, scheduling, reliability) and `docs/COST.md` (free-tier statement).

| Requirement | Where |
|---|---|
| Research, facts vs assumptions | `app/research.py` (facts must cite a fetched URL or are demoted to assumptions) |
| Adaptive interview, skip, edit, profile | `app/interview.py`, UI *AI interview* / *Profile* |
| Source discovery + justification | `app/discovery.py` (LLM proposes → network verifies → `reason` stored) |
| Crawler, dedupe, history, robots | `app/crawler.py`, `app/fetch.py` |
| Analysis, 3 separate trust measures, ranking | `app/analysis.py` |
| Brief with evidence appendix | `app/brief.py` (items without valid record ids are dropped) |
| Internal CSV/Excel/PDF/TXT | `app/internal.py` |
| Weekly job, monthly audit, failure log, manual trigger | `app/scheduler.py`, `app/audit.py` |
| Context-change reassessment | `app/audit.py: reassess` |

## Known limitations (be upfront in your demo)
- Customer-voice sources use `ddgs` search results (title/snippet + link) for forum sites such as Reddit/Quora rather than crawling them directly, because their robots.txt disallows crawlers. Records are labelled *anecdotal*, never "verified".
- Google News RSS and HN Algolia are consumed through their public feed/API endpoints (robots not applied to machine-readable feeds); HTML pages always honour robots.txt, rate limit (`CRAWL_DELAY_SECONDS`) and use an identifiable user agent. Set a real contact in `CRAWLER_UA`.
- Search-result records have no publication date (shown as "not stated"); their evidence strength is capped accordingly.
- Free LLM tiers rate-limit; calls retry with backoff. Source discovery for ~8 competitors takes a few minutes.
- No authentication on the dashboard; run locally or behind your own auth/proxy.
